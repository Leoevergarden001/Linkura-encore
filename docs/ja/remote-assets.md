# リモートアセットサーバー（iOS、任意）

通常、iOS オフライン版のアセットはすべて端末に転送します（[iOS のビルドとインストール](ios.md)を参照）。代わりに、アセットを自分のサーバーやオブジェクトストレージに置き、アプリが初めて必要になったときにダウンロードすることもできます。端末に二十数 GB を一度に転送する必要がなくなり、新しいアセットバージョンの公開にもパソコンが不要になります。

変わるのはアセットの取得方法だけです。API とプレイヤーのセーブデータは、これまでどおり端末上のオフラインサーバーがネットワークなしで処理します。

## 仕組み

```
ゲーム（Unity）── http://127.0.0.1:52680/a/<パス> ──▶ dylib 内のオフラインサーバー
                                                   ├─ Documents/LinkuraOffline/assets/<パス> にファイルあり：そのまま返す
                                                   └─ なし：GET <remoteAssetBase>/<パス>（NSURLSession、HTTPS）
```

- IPA の metadata では、公式のアセット URL がすでに `http://127.0.0.1:52680/a` に書き換えられています。Unity が平文 HTTP を許可するのはループバックだけなので、ゲーム自体は常に端末内にだけアクセスし、オフラインサーバーがリモートへのリクエストを代行します。
- `/v1/archive/` 系 API のレスポンスに含まれる公式 CDN の URL（カバー画像、動画のプレイリスト、モーションリプレイのエントリ）は、ローカルの `/a/` に書き換えられ、同じプロキシを通ります。
- プロキシがリモートから中継するのは 200 と 206 だけで、それ以外はすべて**本文なしの 404** を返します。ゲームのダウンローダーはステータスを見ずに本文をキャッシュファイルに書き込み、その長さから続きを取得するため、本文付きのエラーページはそのキャッシュファイルを恒久的に壊してしまいます。

## リモートサーバー上のパス

リモートサーバーは、ゲームがリクエストするパスでファイルを提供します。`<remoteAssetBase>` 以降の部分は `/a/` 以降の部分と同じです。

| パス | 内容 |
|---|---|
| `raw/<先頭2文字>/<RealName>` | カタログファイル、メディア（`.acb`、`.awb`、`.usm`）、生データ（マスターデータ `.tsv`、ストーリースクリプトなど）。ResourceType 128/192 |
| `ios/<先頭2文字>/<RealName>` | iOS 用アセットバンドル（ResourceType 1） |
| `archive/alst/…` | モーションリプレイ（任意）。各 `.md` エントリの `path` を `http://127.0.0.1:52680/a/archive/…` に変更し、プレイリストとセグメントもプロキシを通るようにします |
| `archive/hls/<ディレクトリ>/…` | 動画リプレイの HLS プレイリスト（任意） |
| `with_meets/`、`feslive/`、`with_station/` 配下の `thumbnail_image/*.jpg` | アーカイブのカバー画像 |
| `version.json` | 公開するアセットバージョン（後述） |

RealName はカタログで決まります。カタログ、`RealName`、キャッシュファイルの関係は[アセットの準備](resources.md)をご覧ください。

## config.json

アプリの `Documents/LinkuraOffline/config.json` に記述します。

```json
{
  "port": 52680,
  "resVersion": "R2606002@...",
  "remoteAssetBase": "https://<アセットサーバー>/a",
  "remoteAssetKey": "<この端末のキー>",
  "motionReplays": false
}
```

| フィールド | 役割 |
|---|---|
| `remoteAssetBase` | リモートアセットのベース URL。設定するとプロキシが有効になり、起動時に接続確認も行います（結果は `server.log`） |
| `remoteAssetKey` | 任意。プロキシのすべてのリクエストにヘッダー `x-linkura-key: <値>` を付けます。サーバー側でキーのないリクエストを拒否できます（CDN のファイアウォールルールなど）。端末ごとに別のキーを使えば、漏れたキーだけを無効にできます |
| `resVersion` | アセットバージョン。`remoteAssetBase` を設定している場合は、起動時に `<remoteAssetBase>/version.json`（`{"resVersion": "..."}`）を読み、その値を使います。読めないときはこの値を使います。待つのは起動後 6 秒までで、ゲームが止まることはありません |
| `motionReplays` | 任意、既定は `true`。`false` にすると、With×MEETS のアーカイブ詳細から `archive_url` を除き、公式の `video_url` を戻して動画リプレイで再生します。モーションデータを置いていないサーバー向けです。Fes×LIVE は常に 3D リプレイを開くため影響しません |

新しいアセットバージョンを公開するには、新しいファイルとカタログをサーバーに置き、`version.json` を更新します。端末は次回起動時に新しいカタログを同期し、変更されたファイルだけをダウンロードします。

## プロキシの転送方式

- **分割ストリーミング**：大きなファイルは 4 MB ずつ Range でリモートに要求し、届いた分からゲームに書き戻します。現在の分を送っている間に次の分を先読みします。1 回の転送で保持するのは最大 2 つ分なので、418 MB のストーリー動画でも丸ごとメモリに載ることはありません。途中で失敗した場合は接続を切り、ゲームのダウンローダーが Range で続きを取得します。
- **クライアントの Range** はそのまま守ります（`bytes=a-`、`bytes=a-b`）。`content-range` も正しく返します。
- **同時接続数**：リモートへの接続は最大 12 本で、後述のダウンロード並列数パッチに合わせています。

## ダウンロード並列数

ゲームのダウンローダー（`Hailstorm.StardustDownloadWorker` → ネイティブライブラリ `Blitz.Stardust`）は、同時にダウンロードするファイル数を `AdaptiveConcurrencyController` に問い合わせます。1/2/3/4 の固定テーブルで、測定したスループットが 80/130/180/260 Mbit/s を超えたときだけ段階が上がります。遠いサーバー（1 リクエストあたり 0.2～0.6 秒）ではスループットが最初の段階に届かず、クライアントは 1 ファイルずつダウンロードするため、5 万を超えるファイルの新規インストールに何時間もかかります。

`ios-offline-stage` は既定で 2 つのパッチを当てます。`RecommendedDownloaderNum` が常に 12 を返し、ネイティブダウンローダーの上限を 4 から 12 にします。実測で、毎秒約 2 ファイル・0.9 MB/s から毎秒約 17 ファイル・11 MB/s に改善しました。元の動作を残すには `--keep-download-concurrency` を指定します。

## 動画リプレイのプレイリスト

アーカイブの動画リプレイは Mux の HLS で、画質ごとに `.m4s` ファイルが 1 つあり、各セグメントは `EXT-X-BYTERANGE` で指定されています。各 `.m4s` が公開されている HLS アーカイブのどこにあるかが分かれば、**静的な**プレイリストを生成できます。マスタープレイリストは画質 1 つとメイン音声だけを残し、メディアプレイリストの URI をそのアーカイブファイルの絶対 URL に変え、バイト範囲にオフセットを加えます。サーバーが置くのは数十 MB のプレイリストだけで、セグメントはプレイヤーがアーカイブから直接取得します。

プレイヤーはセグメントを直接取得するため、そのリクエストには `x-linkura-key` が付きません。キーで保護されるのは、プロキシを通るプレイリストだけです。

## パソコンでのテスト

ホスト版のサーバーも同じプロキシに対応しており、NSURLSession の代わりに curl を使います。

```sh
server/build-host.sh
server/build/host/linkura-offline-server --data /tmp/offline-data \
  --remote-asset-base https://<アセットサーバー>/a --remote-asset-key <キー> \
  [--remote-chunk-bytes 4194304] [--res-version-file version.txt] [--motion-replays off]
```

`server/tests/smoke_test.py` はローカルの Range サーバーを相手に、キーのヘッダー、分割ストリーミング、クライアントの Range、本文なしの 404、動的な resVersion、`motionReplays` を無効にしたときの動画リプレイを確認します。
