# はじめに

## 対応バージョン

| プラットフォーム | クライアント | アセットバージョン | 説明 |
|---|---|---|---|
| Android | 5.1.0（versionCode 109563） | `R2606002@RQMqABAxdj0b5c8TKh4+PNDUYQ==` | サービス終了前の最後のオンライン版です。モジュールはクラスとメソッドを名前で探すため、アドレスに依存しません。 |
| iOS / iPadOS | 5.0.1 | 同上（5.1.0 のアセットを使用） | パッチは固定アドレスを使い、元のバイト列を一つずつ検証します。このビルドだけに対応します（復号済み IPA の SHA-256 は `5d65a125b7701f51…` で始まります）。 |

アセットバージョンによってクライアントが受け入れるキャッシュが決まるため、お手元のキャッシュと一致させてください。既定値は `android/app/src/main/assets/offline-config/client-res.json` にあります。

## ご自身で用意するもの

1. **クライアント**：Android 5.1.0 の APK、または iOS 5.0.1 の**復号済み** IPA が必要です。App Store から取得した IPA は暗号化されています。
2. **アセットキャッシュ**：端末のゲームがダウンロード済みの `D/`（アセット）、`M/`（データベース）、および PlayerPrefs 内の対応する**ストレージキー**が必要です。キーがなければ、クライアントは別のインストールのキャッシュとみなして無視します。[アセットの準備](resources.md)をご覧ください。
3. **ツールチェーン**：
   - オフラインサーバーのホスト版：C++23 コンパイラー（clang 16+ / gcc 13+）と CMake（内蔵データのヘッダー生成にだけ使用）。
   - Android：Android SDK、NDK 26.3、JDK 17。LSPatch による再パッケージ化には Java 21+ が必要です。
   - iOS：Xcode（iPhoneOS SDK）と Apple アカウント。無料の Personal Team でも利用できますが、署名の有効期間は 7 日です。
   - Python 3.10+。データ生成には PyYAML、アセットツールには `lz4` と `cryptography`、iOS アセット変換にはさらに `UnityPy` が必要です。

## コードの取得

```sh
git clone --recurse-submodules <repo>
# クローン済みの場合：
git submodule update --init
```

`third_party/link-like-diff` は YAML 形式のゲームのマスターデータです。内蔵データを再生成する場合だけ必要です。

## 次の手順

- Android：[ビルドとインストール](android.md)
- iOS / iPadOS：[ビルドとインストール](ios.md)
- まずパソコンでオフラインサーバーの動作を見る場合は、`server/build-host.sh && python3 server/tests/smoke_test.py` を実行してください。[オフラインサーバー](server.md)も参照してください。

## プライバシー

端末から取り出した PlayerPrefs、バックアップ、`M/` 内のデータベースは元のインストールに属します。`app` データベースには元のアカウントのプレイヤー ID も含まれます。パッケージ化ツールは既定でカタログDBとマスターデータDBを新しいストレージキーに置き換え、`app` データベースを含めません（[アセットの準備](resources.md)を参照）。それでも元のエクスポートとバックアップはご自身のストレージだけに保管してください。リソースパック自体もゲームのコンテンツなので共有しないでください。これらをリポジトリにコミットしないでください。`.gitignore` は誤った場所に置いたファイルまで保護しないため、コミット前に内容を確認してください。
